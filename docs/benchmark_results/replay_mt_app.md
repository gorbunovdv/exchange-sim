# replay_mt_app

`ReplayOrderGenerator`, multi threaded design. Label `master_2026-10-14`, git revision
`8eef9cc598a92a1a5bdc5324e6af95148a63b018`.

Please note that the multi threaded design is not optimized for latency: with `max_pending_transactions = 10` the
latency includes the time requests spend waiting in the SPSC queues, so it is not comparable with the callback and event
loop apps. The number to look at here is the throughput in the summary.

```
just evaluate ./configs/dmitrys-ubuntu.json --apps replay_mt_app --labels master_2026-10-14 --percentiles 50 99 99.9
```

Groups with fewer than 10000 events in any run and groups with more than 10 trades are not printed by `just evaluate`.
All latencies are nanoseconds.
